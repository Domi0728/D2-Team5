# Run and verify this update

This is a complete incremental source release based on Week 5. Preserve the existing data directory. Stop the old server and make a backup before updating sources. The schema remains version 2.

On Ubuntu/WSL with the existing project dependencies installed:

```sh
make clean
make
./build/ride_server --migrate
make test
./build/ride_server
```

For a new setup, first follow README.md to install dependencies, create the administrator and seed demonstration locations. Do not recreate accounts or reset an existing database. The tests use their own temporary databases.

Matching uses the existing endpoint and query fields:

```sh
curl "http://127.0.0.1:8080/api/matches?origin_id=1&destination_id=2&departure_at=$DEPARTURE_AT&tolerance_minutes=15&min_seats=1&sort=default" \
  -H "Authorization: Bearer $STUDENT_TOKEN"
```

Set DEPARTURE_AT to future Unix seconds and STUDENT_TOKEN to an approved student's login token. Successful output remains an array of ride objects, with time_difference_seconds and shared_completed_rides. No compatible rides returns []; unsupported sort values return 422. The frontend still needs to display appropriate empty-result guidance.

A ride whose organiser is restricted, rejected or suspended no longer appears in matching results. Removing the restriction restores eligibility if all other conditions hold. Accepting an invitation still rechecks eligibility and remaining seats transactionally.

Files changed: src/rides.c, tests/test_api.py, README.md; new dated progress/run/test documents and patch. The normal compiler uses -Wall -Wextra -Wpedantic -Wformat=2. In the execution container, dependencies were in tmp/cdeps; the exact build command appears in TestResults_2026-11-18.txt. On a provisioned Ubuntu/WSL installation use plain make.
