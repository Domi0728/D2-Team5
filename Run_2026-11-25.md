# Run and test

This is a complete source release continuing the 2026-11-18 package. Back up the existing database before updating; preserve your data directory. No new migration is required. Install the dependencies listed in README.md on Ubuntu/WSL, then run from the project root:

```sh
make clean
make
./build/ride_server --migrate
make test
./build/ride_server
```

For a new demo database only, follow README.md to create an administrator and seed locations. Do not reset an existing database. Tests use temporary databases. The normal test build includes -Wall -Wextra -Wpedantic -Wformat=2. The exact container dependency overrides are recorded in the test log; locally installed development packages require plain make.

## Accept an invitation

Set STUDENT_TOKEN to the recipient's token, INVITATION_ID to a pending invitation and RIDE_VERSION to the current ride version. Keep the same key and exact body when retrying an uncertain request. Do not use a new key merely because a response was lost.

```sh
ACCEPT_KEY="$(cat /proc/sys/kernel/random/uuid)"
ACCEPT_BODY="{\"action\":\"accept\",\"expected_version\":$RIDE_VERSION}"
curl -sS -X POST "http://127.0.0.1:8080/api/invitations/$INVITATION_ID/respond" \
  -H "Authorization: Bearer $STUDENT_TOKEN" \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: $ACCEPT_KEY" \
  --data "$ACCEPT_BODY"
```

A successful response retains id, status=ACCEPTED, and ride. Repeating that same command replays the stored success without an extra membership or notification. Retry using the same authenticated user and original key/body; the current implementation retains idempotency records for 24 hours. Fetch GET /api/rides/{id} when a current ride view is needed: replay returns the original response snapshot.

For a valid invitation to a ride whose last seat has just been taken, expect HTTP 409 with error.code GROUP_FULL and message "No seats available; no seat was allocated". Existing error object shape is unchanged. Different content with the same key returns HTTP 409 KEY_REUSED. If the ride itself was materially edited, refresh it and follow the existing reconfirmation flow.
